# v0.4 統計回顧面板與存檔安全網 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 為 v0.4 交付三件事，並完成釋出戰役的全部準備工作：
1. **D2 統計與回顧面板**：把使用者已經積累、但「只存在於 30 條文字日記裡」的專注歷史 [F10]，變成一眼可回看的數字層——今日/本週/本月/累計、一起度過的時間、圖鑑完成度、當前成長階段。全部純本地計算，不新增持久化欄位、不新增上傳行為。
2. **D3 存檔匯出/匯入安全網**：讓「圖鑑與總時長」這份本機唯一副本的資產 [F11] 可以一鍵備份與恢復，匯出→匯入往返無損。
3. **釋出物料與 D1 分發戰役規劃**：官網中英補全、30–45s 演示影片、Release notes 草稿、六渠道投放節奏與回應機制。**物料全部就緒，對外發布動作逐一等你確認後才執行。**

成功定義（沿用分析文件 5.1）：統計數字與日記條目一致性有測試；匯出匯入 100% 往返無損；統計文案過「無壓力」審查（無斷籤渲染、無懲罰性表述）；釋出物料三件齊備。

**Architecture:** 改動面收斂在既有架構內，不引入新框架、新依賴、新資料通道：

- **Go 後端（state.go）**：統計派生全部在 `snapshotLocked` 路徑擴充套件——今日重算邏輯 [C1] 已確立「派生資料每次快照即時算、不落盤」的模式，周/月/天數聚合是同一函式的日期字首引數化（已由技術依據確認 [T1][T5]）。前端 `apply()` 每次收到完整 Snapshot 整體 render，新增面板直接消費同一 Snapshot，無需新資料通道 [T2]。

- **無新持久化欄位、無新 RPC 頻道之外的任何網路行為。**

## 七、D2 統計與回顧面板

### 7.1 資料模型：三分類明細

| 指標 | 來源 | 分類 | 是否持久化 |
|-|-|-|-|
| 今日專注分鐘/輪 | TodaySecs/TodayRounds，snapshotLocked 即時重算（含進行中會話） | 現成，已在上屏 [C1] | 否（現狀即不落盤） |
| 累計專注分鐘/輪 | TotalSecs / Completed 持久欄位 | 現成 [C3] | 是（既有欄位，不動） |
| 本週/本月專注分鐘/輪 | Records 按日期聚合（照 C1 模式換周/月範圍） | 需 records 聚合 | 否，派生 |
| 一起度過的時間（天數） | Records 的日期去重計數 | 需 records 聚合 | 否，派生 |
| 本週有專注的天數 | Records 聚合，限本週範圍 | 需 records 聚合 | 否，派生 |
| 圖鑑完成度 x/15 | len(Visitors) / 15（15 種硬編碼）[C4] | 現成資料，新展示 | 既有 |
| 最近到訪的朋友 | Visitors 的 Date + Visits | 現成 [C4]，圖鑑已顯示「來過 N 次」 | 既有 |
| 當前稱號 + 下一檔距離 | Completed 分檔規則（<3 初生 / <12 萌芽 / <24 繁盛 / ≥24 小小綠洲）[C5] | 現成規則，新展示 | 既有 |
| 植物狀態 | plantBed：株數 = min(8, 1+floor((completed−1)/3))，每株三階 [C6] | 現成規則，新展示 | 既有 |

**需新增派生**的只有三處：周/月聚合、天數聚合、下一檔距離計算——全部是展示層派生，透過 snapshot 下發，前端零聚合邏輯。聚合放 Go 後端 `snapshotLocked` 而非 JS（TodaySecs/TodayRounds 即該模式 [C1][T5]）。records 每條僅 5 欄位（id/task/seconds/completed/date，只存整數秒、date 為寫入時刻 [T1]）——「從幾點到幾點」「本輪計劃多久」無欄位可算，不在面板範圍；天數 = records 的日期去重計數，受 1000 條截斷約束（口徑見 7.2）。

### 7.2 已知口徑限制（誠實標註，不掩蓋）

Records 只保留最近 1000 條（新→舊 prepend 截斷）[C2]：**「一起度過 N 天」是留存記錄範圍內的口徑**——重度使用者早期日期可能已被截斷，累計天數可能低於真實歷史。TotalSecs/Completed 永久保留，所以**累計時長/輪數精確**。因此文案只說「一共 N 天」（基於留存記錄），不說「歷史全部天數」，tooltip 亦不承諾完整性。1000 條邊界下的聚合正確性納入測試。

### 7.3 為什麼不新增持久化欄位（依據）

1. **架構先例**：TodaySecs/TodayRounds 本來就不落盤，每次快照從 Records 重算 [C1]——周/月/天數是同一邏輯的日期引數化，遵循既有模式，不是新發明。
2. **資料完備**：每條 Record 帶 RFC3339 Date [C2]，周/月/天數可完全重建，不丟資訊；持久化副本反而引入兩份資料不一致的風險。
3. **遷移成本**：新增持久化欄位要過 newAquarium 校驗鏈與舊存檔相容邏輯 [C7]，且加重 D3 匯出格式的版本相容負擔。
4. **效能可接受**：1000 條線性掃描是今日重算已在跑的開銷量級 [C1]，周/月聚合同階。

### 7.4 UI 設計【Q1/Q3 已定】

- **第一屏（預設可見，不改）**：底部統計區「今天的小積累」三格（今天分鐘/今天輪數/朋友數）保持現狀——它就是「今日」層。
- **第二屏（新增，預設摺疊）**：新增 `details` 摺疊區「**這段時間**」，位於「專注日記」摺疊區之前。展開後自上而下：

  1. 本週專注（分鐘 · 輪數）+ 本週有專注的天數
  2. 本月專注（分鐘 · 輪數）
  3. 一起度過的：累計時長（沿用「已經一起度過 X 分鐘，完成 N 輪專注」句式 [C12]）+ 一共 N 天
  4. 圖鑑：X / 15，下一行最近到訪的朋友
  5. 成長：當前稱號 · 下一階段提示（沿用 growth-label / next-growth 現有句式 [C5]）
  6. 尾註一行：「這些數字只儲存在你的電腦上。」（呼應官網隱私承諾 [F11]）
- **為什麼摺疊而非直接鋪開**：護欄要求「新增機制預設不可見、由使用者主動發現」；`details` 是倉庫已有互動模式（專注日記），零新互動成本 [C9]；統計是低頻回看，不應擠佔第一屏的「今天」與海底畫面。
- **掛件模式：不顯示統計**【Q3】：compact 模式本來就把整個底部統計區隱藏（`display:none`）[C11]。新增回顧面板落在 bottom-grid / details.journal 容器內，兩者已在掛件模式隱藏，不破壞掛件佈局 [T2]。

### 7.5 空態設計

- **全新使用者（0 條記錄）**：面板摺疊區標題下顯示「完成第一輪，這裡開始有故事。」（對齊現有空態「你的海底，正在等待第一個故事。」句式 [C12]）；展開後各指標不顯示 0 值表格，只顯示一句引導 + 尾註。

## 八、D3 存檔匯出/匯入安全網（W2 實施，本輪不做）

### 8.1 匯出格式設計

- **形態**：單檔案 JSON，人類可讀。
- **頂層結構**：`{ "version": 1, "app": "little-reef", "exportedAt": "<RFC3339>", "aquarium": { …存檔內容… } }`。帶版本殼而非裸 aquarium.json 的理由：裸檔案無法區分「存檔」與「任意 JSON」，無法承載未來格式演進；revision 只是前端丟棄過期快照的新鮮度戳（app.js:54）、與資料遷移無關 [T5]——獨立 version 殼與 revision 解耦。
- **aquarium 欄位集合 = Snapshot 全量**：{revision, preferences, session, completed, totalSecs, todaySecs, todayRounds, records, visitors, lastVisitor, notice, fedSession, nowMs}——aquarium.json 本身就是 `snapshotLocked()` 的直接 marshal [T5]，匯出複用 `saveLocked` 序列化段 [T4]。
- **瞬態欄位處理【Q8】**：匯出時原樣保留；匯入時忽略 todaySecs/todayRounds/nowMs，由匯入後的首個快照按當天重算。
- **進行中會話**：不做匯出前歸一化——`newAquarium` 載入時本就強制 running→paused、清空 LastVisitor [C7][T4]，匯入路徑複用同一處理。
- **往返無損定義**：同版本內「匯出→匯入→再匯出」byte 級等價——Go `json.Marshal` 鍵序穩定 [T5]；跨版本只承諾欄位級語義等價（未知欄位靜默忽略、缺欄位取零值 [T5]）。
- **匯入校驗順序**：① JSON 可解析 → ② 頂層欄位識別 → ③ aquarium 內容過 newAquarium 校驗鏈 [C7][T4] → ④ 全部透過後才寫入。任一步失敗：**當前存檔零改動**。錯誤文案複用現有基色。
- **失敗回滾**：寫入走既有 change() 模式——儲存失敗恢復 previous state 並報錯 [C7]。
- **版本演進**：version 2+ 出現時舊版可匯入則匯入、不可匯入則明確報「這是更新版本的存檔，需要先升級小海底」。

### 8.2 邊界場景

| 場景 | 行為 | 文案（過護欄） |
|-|-|-|
| 舊版本存檔（v0.3 時期直接複製的 aquarium.json） | 可匯入：載入對未知/缺欄位靜默容忍 [T5]；裸 aquarium.json 與帶殼檔案兩者都接受，按「有無 version/app 殼欄位」分流識別 | 「這是小海底的存檔，已安全匯入。」 |
| 損壞檔案 / 非 JSON | 校驗第①②步失敗，零改動 | 「這個檔案不是小海底的存檔，什麼都沒有改動。」 |
| 內容欄位越界（如負數時長） | 校驗第③步失敗，零改動 | 「存檔內容有問題，沒有匯入。你的海底保持原樣。」 |
| 更新版本的存檔 | 拒絕匯入 | 「這是更新版本的存檔，先把小海底升級到最新版。」 |
| 匯入會覆蓋現有資料 | 匯入前確認彈層 | 「匯入會替換現在的海底。建議先匯出一份當前存檔。」 |

### 8.3 UX 設計【Q4】

- **入口**：設定對話方塊現有「檢查更新 / 問題回饋」之後新增一節「**備份與恢復**」，兩個按鈕：「匯出存檔…」「匯入存檔…」[C10]。
- **成功文案**：匯出「存檔已儲存到 <檔名>，收好它，隨時可以恢復。」；匯入「海底回來了，一切如初。」
- **檔案對話方塊**：mygo v0.6.0 的 `Dialog.Save` / `Dialog.Open`（darwin/windows/linux 三端有後端實現 [T4]）——倉庫此前僅用過 `Shell.OpenExternal`，首次接入需真機冒煙。瀏覽器模式【Q9】：匯出=觸發檔案下載、匯入=檔案選擇 input。
