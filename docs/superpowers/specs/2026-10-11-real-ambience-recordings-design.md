# 背景音換成真實錄音 · 設計

- 日期：2026-10-11
- 狀態：已批准；實施時的調整見 docs/superpowers/plans/2026-10-11-real-ambience-recordings.md 的“與設計文件的差異”
- 分支：`feat/real-ambience-recordings`

## 背景

20 種背景音目前全部由 `web/audio.js` 即時合成：隨機噪聲經一階濾波，再乘固定週期的正弦起伏，每條 18 秒迴圈。聽起來不真實，原因主要有：

- 起伏週期固定（海浪、風都是 9 秒一個來回），很快能聽出規律；
- 鳥鳴、蟬、蟲鳴、氣泡都是純正弦掃頻，像電子提示音；
- 事件位置每 18 秒重複，例如雷雨裡的三聲雷每次都在同一時間點；
- 雨聲沒有雨滴，只有一層嘶聲；咖啡館人聲、車流本來就很難靠合成做像。

使用者回饋：“當前這些白噪音不真實。”

## 目標

除粉噪外的 19 種聲音換成真實的實地錄音，聽感接近真實環境。開關、音量、淡入淡出、專注時自動播放、完成提示音等互動保持不變。

## 成功標準

1. 19 種聲音都來自 CC0 實地錄音；粉噪仍為即時合成。
2. 迴圈聽不出接縫、不斷音；時鐘、木魚的節奏在接縫處不亂；視窗收進托盤後持續播放。
3. 每條錄音的響度與它替換的合成聲音一致（±1 LU），真峰值不超過 −1 dBTP。
4. `web/sounds/` 總計約 25 MB，上限 30 MB。
5. 使用者試聽透過；不滿意的條目從備選中替換。
6. Go 測試全部透過；瀏覽器模式下 20 種聲音都能解碼播放，控制檯無報錯。

## 不做的事

- 不改聲音列表：ID、名稱、順序、Go 端偏好校驗都不變。
- 不做隨機片段拼接或其他“永不重複”的生成方式。
- 不做多種聲音疊加混音。
- Linux 缺少 MP3 解碼外掛時，不回退到舊的合成聲音，只給出提示。

## 素材

### 來源與授權

- 只用 Freesound 上 CC0 1.0 授權的錄音。CC0 不要求署名，仍在 `THIRD_PARTY_NOTICES.txt` 列出每條錄音的標題、作者、連結和許可。
- 原始檔取 Freesound 公開的高位元速率試聽版（OGG Vorbis，約 192 kbps，保留原始取樣率，免登入）。原始檔案需登入下載，以後可替換。

### 挑選規則

- 優先下載量和評分高、44.1 kHz 以上立體聲、時長足以截出乾淨片段的錄音。
- 用頻譜圖和響度統計排除：削波、麥克風風噪、電流哼聲、能聽清內容的人聲，以及喇叭、警笛、關門等突兀事件。
- 每種另備兩條候選，以註釋記在構建指令碼的表裡，試聽後直接替換。

## 處理與打包

### `build-sounds.sh`

放在倉庫根目錄，與 `package-macos.sh` 並列，只在更換錄音時執行，依賴 ffmpeg（含 libmp3lame）和網路。平時構建和執行都不需要它。

- 頂部一張表：聲音 ID、Freesound 編號、試聽版地址、擷取起點、時長、目標響度。
- 每條錄音的步驟：
  1. 下載到 `${TMPDIR:-/tmp}/little-reef-sounds/`，已下載的跳過；
  2. 按起點和時長擷取；
  3. 測量整體響度，線性增益到目標值；
  4. 真峰值超過 −1 dBTP 時加柔和限幅；
  5. 編碼為 MP3（LAME VBR，預設 `-q:a 2`），保留原始檔的取樣率和聲道數，寫入 `web/sounds/<id>.mp3`；
  6. 複測響度與真峰值，列印結果。
- 木魚：取真實單擊取樣，按週期 L = N × 1.35 秒排列 N 下，每下的時間偏移不超過 ±25 毫秒、力度起伏不超過 ±15%，隨機數用固定種子。排好的序列按週期 L 重複，覆蓋接縫處的交叉淡化區，迴圈時內容完全一致。
- 超出 30 MB 時，依次縮短事件型片段，或把編碼質量降到 `-q:a 3`。

### 嵌入

生成的 MP3 直接提交進 git，不用 Git LFS。現有的 `//go:embed web` 會把它們打進程式，播放時不聯網。

## 播放（`web/audio.js`）

### 介面

`Soundscape` 對外不變：`unlock`、`set(playing, sound, volume)`、`chime`、`dispose`。`app.js` 與 Go 端不改。

### 載入與迴圈

1. `fetch("sounds/<id>.mp3")`，再用 `decodeAudioData` 解碼。
2. 在解碼後的緩衝區裡原地做接縫：從 `start` 秒起取迴圈長度 `loop`，把 `[start + loop, start + loop + fade)` 這一段與 `[start, start + fade)` 做等功率交叉淡化（前者淡出、後者淡入），結果寫回前者。
3. 設定 `loopStart = start + fade`、`loopEnd = start + loop + fade`，用 `AudioBufferSourceNode` 的原生迴圈播放，不依賴定時器。
4. 預設值：`start` 為 0.25 秒（避開編碼器在開頭補的靜音），`fade` 為 3 秒，`loop` 取最大值，使 `loopEnd`（即 `start + loop + fade`）落在距檔案末尾 0.25 秒處。
5. 時鐘、木魚、音樂盒在提示表裡寫明 `start`、`loop`、`fade`：
   - 時鐘、木魚的 `loop` 取整數拍，`start` 落在兩下敲擊之間的空隙，`fade` 約 0.15 秒，交叉淡化只發生在空隙裡；
   - 音樂盒的 `loop` 取整首，在曲尾餘音處銜接。

### 起播位置

音樂盒從曲頭開始；其餘聲音每次從迴圈區間內的隨機位置開始。

### 快取與競態

- 按聲音快取解碼的 Promise，只保留最近兩種；每種解碼後約佔 20–35 MB 記憶體。
- 載入失敗的 Promise 從快取移除，下次可重試。
- 沿用現有的 `sequence` 校驗，載入完成後再校驗一次，過期的請求不出聲。

### 錯誤處理

讀取或解碼失敗時，呼叫 `onStatus("這段聲音暫時無法播放，計時不受影響", true)`，介面彈出提示，計時照常。

### 粉噪與舊程式碼

粉噪保留原合成演算法（18 秒），改用新的接縫處理。其餘 19 種的合成程式碼刪除。

## 測試與驗證

- Go 測試：每種聲音（粉噪除外）在嵌入的 `web/sounds/` 中都有非空的 MP3 檔案。
- 瀏覽器模式自動檢查（一次性指令碼，不提交）：
  - 逐個載入 20 種聲音，確認解碼成功、迴圈區間合理；
  - 接縫處的樣本跳變不超過片段內的典型值，接縫前後短窗 RMS 連續；
  - 點遍介面上的聲音按鈕，控制檯無報錯。
- 響度：指令碼複測每條在目標 ±1 LU 內，真峰值不超過 −1 dBTP。
- 體積：統計 `web/sounds/` 總大小，不超過 30 MB。
- 人工：使用者在桌面版逐個試聽，不滿意的從備選替換後重跑指令碼。

## 風險

- 實現者無法試聽，只能靠資料挑選和檢查，最終以使用者試聽為準。
- Linux 的 WebKitGTK 缺少 MP3 解碼外掛時，19 種錄音無法播放（粉噪仍可用）：README 註明依賴，介面給出提示。
- 用的是試聽版而非原始檔案，音質略低，對環境聲影響很小；以後可以用 Freesound 賬號下載原始檔案替換。
- 記憶體：每種聲音解碼後約 20–35 MB，最多同時快取兩種。

## 試聽後的調整（2026-10-11）

使用者試聽後按耳朵選定了以下改動，已合併：

- 氣泡、煮沸、沙漠、咖啡館、車流聽起來嘈雜，換成更安靜的錄音：水箱裡的大氣泡、小火慢燉番茄醬、空曠平原上的輕風（作者用嘴吹氣加混響做成，不是實地錄音）、哥本哈根的小咖啡館、遠處的高速公路。煮沸、沙漠、咖啡館、車流的目標響度比原合成聲音低 3 LU。
- 音樂盒改放整首帕赫貝爾《卡農》，按鈕顯示為“卡農”，聲音 ID 仍是 musicbox。Freesound 上沒有 CC0 的音樂盒版卡農，因此用了美國空軍樂團 Strolling Strings 2004 年的絃樂演奏（美國政府作品，屬公共領域，來自 Wikimedia Commons）。這是“只用 Freesound 上 CC0 錄音”的唯一例外。整首播完後停頓約兩秒再從頭開始，接縫落在靜音裡。
- 卡農用 VBR 質量 3 編碼，以留在 30 MiB 預算內（合計約 29.7 MiB）。整首解碼後約佔 90 MB 記憶體，超出上面“每種 20–35 MB”的估計。
